Claude's resolved query
--------------------------
Moving daily-location-gallery.html into common/ and making it
?trip=-aware (per your answer) meant it could no longer show a "choose a
trip" screen the way it always could show a "choose a day" screen --
there was nothing to scan. A browser can't list sibling folders on
disk (file:// has no directory API), so this page can't discover trip
folders itself the way the day-picker discovers dates from data already
loaded into memory. This script exists to bridge that gap the same way
every other piece of "the browser can't see the filesystem" data in this
project is bridged: a small build script writes a plain runtime-mirror
.js file the page then loads with a normal <script src> tag.

Built scripts/javascript/build-common-trips-manifest.js, a plain Node
script (no npm dependencies -- fs + path only) that:

  1. Scans the travel-journals/ collection root (two levels up from this
     script) for travel-journal-YYYY-MM-DD folders that contain their own
     trip-info.json. A folder without a trip-info.json yet is silently
     skipped.
  2. For each trip, pulls its title straight out of that trip's own
     trip-info.json {"title": "..."} -- the exact same source
     travel-journals/index.html's own trip cards read, client-side (see
     that page's own top-of-script comment). sub always comes back ""
     now: every trip's journal page is common/journal.html?trip=<folder>,
     a single shared page that computes its own date-range/photo-count
     summary entirely client-side (see that page's own top-of-script
     comment), so there is no static HTML left anywhere to pull a
     build-time subtitle out of -- the field stays in the manifest's
     shape only because common/daily-location-gallery.html's own code
     still reads it. This manifest can't go stale otherwise: re-running
     this script after a trip's trip-info.json changes keeps
     travel-journals/index.html, common/daily-location-gallery.html, and
     common/journal.html's trip picker/title all in sync.
  3. Sorts trips chronologically (oldest first) and writes
     common/data/trips-manifest.js as window.TRIPS_MANIFEST = [ {folder,
     title, sub}, ... ].

Where it lives / how it's used
----------------------------------
    travel-journals/
      common/
        daily-location-gallery.html   <- loads ./data/trips-manifest.js unconditionally
        journal.html                   <- also loads it, to look up its own ?trip= trip's title
        data/
          trips-manifest.js            <- this script's output
      scripts/
        javascript/
          build-common-trips-manifest.js
          build-common-trips-manifest_Instructions.txt   <- this file

travel-journals/index.html (the collection root's own landing page) also
reads window.TRIPS_MANIFEST client-side, for its own trip cards -- see
that page's own top-of-script comment. It used to be regenerated by a
sibling script, build-travel-journal-index.js, since retired; see
scripts/_to_delete/build-travel-journal-index_Instructions.txt.

common/daily-location-gallery.html reads window.TRIPS_MANIFEST for two
things: the trip picker shown when its URL has no ?trip= at all (one
card per manifest entry, linking to ?trip=<folder>), and the masthead
"kicker" line's trip title once a trip IS selected (looked up by
matching ?trip= against each entry's "folder").

DEPENDENCIES
--------------
    Plain Node (no npm packages, no network access needed to run it).

HOW TO RUN IT
---------------
    node scripts/javascript/build-common-trips-manifest.js

  No arguments. Run from the travel-journals/ collection root (or any
  directory -- the script locates the root relative to its own file
  path, not the current working directory).

Initial run (2026-08-27, as part of the daily-location-gallery.html move):
    node scripts/javascript/build-common-trips-manifest.js

  Found 2 trips and wrote common/data/trips-manifest.js:
    - travel-journal-2026-01-14  "🧳 Travel Journal"
    - travel-journal-2026-07-01  "🧳 Travel Journal 2026 Summer"

WHEN TO RE-RUN IT
--------------------
  - A new travel-journal-YYYY-MM-DD folder is added and built.
  - An existing trip's trip-info.json title changes.
  - A trip folder is removed or renamed.

  This is now the ONLY script to re-run for any of these -- both
  travel-journals/index.html and common/daily-location-gallery.html's
  trip picker read this script's output live, so there's no second
  generator to also keep in sync anymore. Safe to re-run any time;
  always rescans fresh and overwrites common/data/trips-manifest.js to
  match exactly what's on
  disk.

Notes and safety
-------------------
- Read-only with respect to every trip folder -- only reads each trip's
  trip-info.json; never writes inside travel-journal-YYYY-MM-DD/ folders.
- Writes exactly one file: common/data/trips-manifest.js (creating
  common/data/ if it doesn't exist yet; overwritten each run).
- A trip whose trip-info.json is missing is skipped rather than
  erroring.
- If zero trip folders are found, the file still generates with an empty
  array -- common/daily-location-gallery.html's trip picker shows a "no
  trips found, run this script" message rather than a blank page.

Update — index.html moved to common/journal.html?trip=<folder> (August 2026)
------------------------------------------------------------------------------
Each trip used to have its own index.html, a byte-identical (except for
title/folder name) client-side-rendered journal page duplicated into
every travel-journal-YYYY-MM-DD/ folder. That page moved to
common/journal.html, one shared copy read via ?trip=<folder> (the same
pattern this script's own daily-location-gallery.html move already
established), and each trip's own index.html was deleted. Since this
script's title source used to be that per-trip index.html's own <h1>,
moving it away meant there was no longer any HTML file to read a title
out of at all -- so a small new file, <trip>/trip-info.json (just
{"title": "..."}), was added as this script's (and build-travel-journal-
index.js's) new title source, and this script's collectTrips() was
switched from fs.readFileSync()-ing each trip's index.html to reading
its trip-info.json instead. See common/journal.html's own top-of-script
comment, build-travel-journal-index_Instructions.txt, and
scripts/_to_delete/build-travel-journal_Instructions.txt (that earlier
retirement's own notes) for the fuller history.
